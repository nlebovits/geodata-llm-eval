# EUDR Workflow Eval — Design

Date: 2026-07-24
Status: proposed, awaiting approval

## Context

`geodata-llm-eval` asks whether a language model can complete a real geospatial
workflow against a cloud-native catalog, and what it costs. Today it asks a
much smaller question than that. `fixtures/questions.yaml` holds **three
example questions**, not thirty — the remaining 27 were never authored — and
all three are single-table aggregations over one Trazo3 parquet.
`fixtures/golden/` contains a README and no fixtures. The harness
(`harness/run.py`, `grade.py`, `pricing.py`, `report.py`) is sound and stays.

Meanwhile `rural-land` already implements the workflow the eval should be
measuring: take a list of Brazilian CAR property IDs, pull those parcels,
match agricultural fields to them under a documented containment rule, measure
forest loss against the EUDR 31 Dec 2020 cut-off, and match each problem
cadaster to the cooperative or buyer that should be contacted about it. That
pipeline is SQL, documented in `MATCHING.md` and `COOPS.md`, and unit-tested.

The missing piece the eval never had was the cadastral layer. It now exists at
`tristangruppwri/cadastral`, and the midstream infrastructure product exists at
`tristangruppwri/soft-commodity-infrastructure`. With all three catalogs
published, the eval can measure the whole chain: cadastral IDs → boundaries →
EUDR deforestation risk → problem plots → the correct commodity infrastructure
by space, location, and commodity served.

**Outcome:** a 30-question, six-stage dependent workflow benchmark whose golden
answers are generated by the `rural-land` SQL rather than typed by hand, plus a
seventh stage that measures whether repeated Sonnet runs agree with each other
and with the oracle.

## Decision: stay in geodata-llm-eval

Do not move out. The framework is right — sealed Docker sessions, deterministic
CSV comparator, imputed-cost accounting, committed transcripts. What is wrong
is the task: one catalog too few and one dimension too flat. `rural-land` is
not a competing home; it becomes the **oracle**.

## The central fix to "expert questions"

Two changes, both structural.

**1. Golden answers are generated, not authored.** `oracle/` vendors the
`rural-land` SQL templates (`cad_extract`, `fields_extract`, `match`,
`coop_match`, `prov/l01`–`l09`) at a pinned commit. `oracle/render.py` fills the
placeholders from `fixtures/pins.json`, runs DuckDB, and emits
`fixtures/golden/qNN.csv` plus `SHA256SUMS`. Regeneration is one command and
reproducible; nobody types an expert answer.

**2. The policy documents are given to the agent.** `MATCHING.md` (2/3
containment, single-parcel OR 25 m-buffered union) and `COOPS.md` (tier order,
commodity routing, widen-to-count, EPSG:5880 distances) encode arbitrary
conventions that are not derivable from data. Withholding them makes stages 3
and 5 unknowable rather than hard. Mounting them turns the eval into the real
question: **can the model implement a written policy spec against live remote
data?** That is exactly the EUDR compliance task.

Consequence: the eval measures implementation fidelity, not guesswork, and
every golden value has a stated derivation a reviewer can check.

## Question set: six stages, 30 questions

### if TG comment is seen, then Tristan Grupp had a review on this to be addressed

Each question declares `stage` and `depends_on`. The chain is the point — an
agent that mis-implements matching in stage 3 should visibly carry that error
into stages 4 and 5, and the grader must be able to say so.

| Stage | Q | Measures | Oracle source |
|---|---|---|---|
| 1 Discovery | 01–04 | navigate three catalogs from metadata alone: collections, row counts, column presence, CRS | direct catalog reads |
| 2 Cadaster resolution | 05–07 | resolve 117 IDs against 8.45M CAR rows; unresolved IDs; município distribution; duplicates and sub-1 ha smallholdings | `cad_extract` |
| 3 Matching (policy) | 08–14 | implement `MATCHING.md`: matched count, by-single-parcel vs by-aggregate-only, both, fraction bounds, per-cadaster field counts, excluded count | `match`, `l07` |
| 4 EUDR deforestation | 15–23 | **classify which Mapbiomas classes are EUDR Annex I relevant**, then loss by Annex I commodity, the audited non-relevant remainder, era bands, loss-year histogram, worst plots | `l01`–`l05`, `EUDR_CROPS.md` |
| 5 Infrastructure | 24–29 | commodity routing, **per-commodity logistics coverage** (which Annex I commodities have no tier), nearest facility in EPSG:5880, widening flags, membership tier, `no_match` reconciliation | `coop_match`, `l08`, `l09` |
| 6 Portfolio decision | 30 | the deliverable: every cadaster non-compliant on an EUDR-relevant crop, with its ranked contact | `l02` ⋈ `l08` |

CAR administrative-status questions were cut (TG: not important); those slots
went to stage 4. Stage 2 shrank to three questions, stage 4 grew to nine.

Grading reports two numbers per stage: raw accuracy, and **conditional
accuracy** (correct given all upstream dependencies were correct). The gap
between them is the error-propagation signal.

**Unit rule:** all deforestation values come from the era-band columns
(`deforestarea0104 / 0509 / 1014 / 1520 / 2124`), converted to hectares as
`band/10000`. `hansen_covered_area` is never referenced by any question or any
vendored query. Area shares use `field_area_ha` as denominator.

**EUDR relevance is the model's job.** No prompt names the in-scope crops. The
agent must map `mbmode24` onto Regulation (EU) 2023/1115 Annex I: 15 → cattle,
39 → soya, 35 → oil palm, 46 → coffee, and 21 (Mosaic of Uses) → cattle. Class
18 is unresolved (negligible area); 20, 40, 41, 47, 48, 62 are outside Annex I;
cocoa and rubber are dropped for Brazil. Sugarcane and rice are traps: real
commodities, outside Annex I.

The mapping carries a `caveat` column, and the eval grades it. Three cases the
agent must keep distinct:

- **21 Mosaic → cattle, `assumed_pasture`.** In scope, but the assumption
  travels with the number.
- **35 Palm and 46 Coffee, `mixed_detection_quality`.** In scope, with a stated
  reliability limit on the field delineation.
- **9 Forest Plantation → wood, `unreliable_detection`, out of scope.** A
  genuine Annex I commodity excluded because Trazo does not reliably detect
  timber — *not* because the regulation omits it. Reporting 9 as "not an EUDR
  commodity" is wrong even though it lands in the right bucket.

That last distinction is the point of the question: regulatory scope and sensor
capability are different reasons to exclude something, and a compliance workflow
that confuses them produces a defensible-looking but wrong answer.
`policies/EUDR_CROPS.md` holds the table, cited to Annex I for commodities and
to Trazo detection quality for caveats.

**Smallholder threshold:** `num_area` < 1 ha, per FAO (2013) *Smallholders and
family farmers*, lower bound of the 1–10 ha description. Lowder et al. (2021)
place 84% of smallholdings under 2 ha; 1 ha selected. `l01`'s
`pct_parcels_over_4ha` is retired.

**Rounding:** goldens emit 1 dp; the vendored `l0*` copies relax the
whole-hectare `round()` calls accordingly.

## Stage 7: expert-workflow consistency check

After the 30 questions, the same session writes `answers/workflow.csv` — one
row per cadaster **flagged non-compliant on an EUDR-relevant crop** (TG: only
non-compliant EUDR-crop cadasters get flagged):

`cod_imovel, annex1_commodity, post2020_loss_ha, top_contact_entity_id, entity_kind, tier, basis, distance_km`

Because the flagged set is agent-determined — it inherits the Annex I
classification from stage 4 — set agreement across runs measures whether models
agree on *who is in scope at all*, not merely on the arithmetic.

`harness/consistency.py` reads the N Sonnet runs and computes:

- **Flag-set agreement** — mean pairwise Jaccard over the set of cadasters
  flagged with post-2020 loss; per-cadaster flag entropy identifies *unstable
  cadasters* by name.
- **Ranking agreement** — Kendall tau-b over the cadaster ordering by
  `post2020_loss_ha`.
- **Contact agreement** — per-cadaster modal `top_contact_entity_id`, the share
  of runs matching that mode, and Fleiss' kappa across runs.
- **Numeric dispersion** — coefficient of variation of `post2020_loss_ha` per
  cadaster.
- **Oracle deviation** — all of the above recomputed against the oracle
  artifact.

The last one is the reason this stage exists: ten runs can agree perfectly and
all be wrong. The report shows `consistency@10` and `accuracy@10` side by side,
plus a per-cadaster stability strip. Output: `results/consistency.json`.

Default N = 10, matching the existing `--passes`.

## Experiment 2: adversarial input set (built now, run later)

`fixtures/lists/mt-adversarial/` — scattered CAR properties carrying
EUDR-non-compliant soy across five Mato Grosso municipalities: **Alta Floresta,
Tabaporã, Juara, Nova Canaã do Norte, Itaúba**. Selected deterministically from
CAR ∩ Trazo3 MT where `mbmode24 = 39` and `deforestarea2124 > 0`.

Injected defects, seeded and reproducible:

- duplicate CARs — same `cod_imovel`, identical geometry
- centroid-only rows — a point where a polygon is expected
- polygons with no ID
- centroids with no ID

Three encodings of the same list, selected by `--input-mode`:

1. `csv` — IDs only
2. `geometry` — GeoParquet/GeoJSON only
3. `split` — CSV and geometry file joined on the ID column

`policies/INPUTS.md` states the expected handling — dedupe on (id, geometry);
point rows resolve by point-in-parcel; ID-less polygons resolve by geometric
match against CAR; ID-less centroids are reported unresolvable, never dropped
silently — so the adversarial cases are graded against a written rule like
everything else. Experiment 1 (Goiás) ships first; this set is built and
committed but not run.

`nlebovits/geodata-llm-eval` PR. The two are coupled — the eval vendors
rural-land SQL at a pinned commit, so rural-land merges first.
